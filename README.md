# Банковское аналитическое приложение

## Описание проекта
Это учебный бэкенд-проект, который представляет собой консольный аналитический движок для обработки, фильтрации и анализа банковских транзакций. Проект разработан с соблюдением принципов чистой архитектуры (SOLID), стандартов кодирования PEP 8 и покрыт развитой сетью автоматических модульных тестов (`pytest`).

Приложение умеет работать с тремя популярными источниками данных (JSON, CSV, Excel), маскировать персональные данные карт и счетов, выполнять регистронезависимый поиск по логам, агрегировать транзакции по категориям трат и устойчиво обрабатывать любые поврежденные форматы данных.

## Архитектура проекта и описание модулей

### 1. Управляющий оркестратор (`main.py`)
Интерактивный консольный интерфейс (CLI), который отвечает за основную логику проекта и связывает все функциональности бэкенда между собой.

**Основные этапы работы интерфейса:**
1. Выбор типа файла для загрузки данных (JSON, CSV или XLSX).
2. Интерактивная валидация ввода и фильтрация транзакций по статусу (`EXECUTED`, `CANCELED`, `PENDING`, `OK`).
3. Хронологическая сортировка операций по дате в любом направлении (по возрастанию или убыванию).
4. Опциональная фильтрация исключительно рублевых транзакций.
5. Фильтрация списка операций по ключевому слову в описании или категории.
6. Агрегированный подсчет транзакций по категориям расходов и красивый пошаговый вывод замаскированного финансового отчета в консоль.

### 3. Аналитический бэкенд-движок

#### `re_bank_search_function.py`
Отвечает за гибкий поиск информации в логах банка.
- `process_bank_search(transactions: list[dict], search_string: str) -> list[dict]`: Выполняет регистронезависимый поиск по подстроке с использованием скомпилированных регулярных выражений. Ищет совпадения одновременно в полях описания операции и её категории.
- Включает вспомогательные изолированные функции безопасного чтения `read_json`, `read_csv` и `read_excel`.

#### `re_count_operations.py`
- `count_operations_by_category(transactions: list[dict], categories: list[str]) -> dict[str, int]`: Принимает массив данных и список интересующих категорий расходов. С помощью встроенного высокоэффективного класса `collections.Counter` подсчитывает точное количество успешных операций по каждой категории, игнорируя пустые или поврежденные строки.

#### `processing.py`
- `filter_by_state(transactions: list[dict], state: str) -> list[dict]`: Универсальный фильтр логов по статусу. Поддерживает как английские ключи (`state`), так и русские названия колонок (`статус`).
- `sort_by_date(transactions: list[dict], ascending: bool) -> list[dict]`: Сортирует транзакции по реальной хронологии объектов времени, безопасно парся любые форматы дат (банковский `dd.mm.yyyy` и ISO).

#### `generators.py`
Содержит памяти-сберегающие (ленивые) генераторы на базе ключевого слова `yield` для обработки гигабайтных массивов данных без переполнения RAM.
- `filter_by_currency`: Итератор по заданной валюте операции.
- `generate_description`: Ленивый вывод описаний транзакций.
- `card_number_generator`: Генератор тестовых шестнадцатизначных номеров карт в заданном числовом диапазоне.

#### `external_api.py`
- `convert_to_rubles(transaction: dict) -> float`: Модуль интеграции со сторонним API конвертации валют (`APILayer`). Если транзакция совершена в USD или EUR, модуль обращается к сети через `requests` и пересчитывает сумму в рубли. Включает в себя локальный кэш транзакций во избежание Rate Limit ошибок API.

### 🛡 4. Модули маскирования и защиты данных

#### `masks.py`
Предоставляет базовые функции маскирования конфиденциальных числовых данных:
- `get_mask_card_number(card_number: str) -> str`: Маскирует номер карты по правилу `XXXX XX** **** XXXX`. Выбрасывает `ValueError`, если длина числовой части карты не равна 16 символам.
- `get_mask_account(account_number: str) -> str`: Маскирует номер счета, оставляя видимыми только последние 4 цифры: `**XXXX`. Выбрасывает `ValueError`, если длина числовой части не равна 20 символам.

#### `widget.py`
Универсальный фасад и конвертер для фронтенда:
- `get_mask_account_card(info: str) -> str`: Самостоятельно определяет тип входящей строки (карта или счет), безопасно перехватывает внутренние ошибки формата и возвращает строку с сохраненным текстовым описанием платежной системы и скрытым номером.
- `get_date(iso_date: str) -> str`: Безопасно преобразует временную строку ISO 8601 в красивый читаемый формат `ДД.ММ.ГГГГ`.

## Автоматическое тестирование (`pytest`)

Проект покрыт развитой сетью автоматических тестов, проверяющих как позитивные сценарии работы бизнес-логики, так и устойчивость к крайним случаям (Edge Cases), невалидным входным данным, сетевым исключениям и падениям сторонних серверов (с помощью `unittest.mock.patch`).

### Примеры реализованных тестов

#### Тесты маскирования (`test_widget.py`)
```python
@pytest.mark.parametrize(
    "info, expected_result", [
        ("Visa Platinum 7000792289606361", "Visa Platinum 7000 79** **** 6361"),
        ("Maestro 7000792289606361", "Maestro 7000 79** **** 6361"),
        ("Счет 73654108430135874305", "Счет **4305"),
    ],
)
def test_get_mask_account_card(info, expected_result):
    result = get_mask_account_card(info)
    assert result == expected_result

@pytest.mark.parametrize(
    "info", [
        "Invalid Format",
        "111223534667587990",
        "some random string",
    ],
)
def test_get_mask_account_card_invalid(info):
    # Устойчивая функция перехватывает невалидный формат внутри и возвращает заглушку
    result = get_mask_account_card(info)
    assert result == "Некорректный формат"
```

#### Тесты обработки времени и дат
```python
@pytest.mark.parametrize(
    "iso_date, expected_result", [
        ("2023-12-31", "31.12.2023"),
        ("2020-02-29", "29.02.2020"),
    ],
)
def test_get_date_standard(iso_date, expected_result):
    result = get_date(iso_date)
    assert result == expected_result

@pytest.mark.parametrize("iso_date", ["", "not-a-date"])
def test_get_date_invalid(iso_date):
    result = get_date(iso_date)
    assert result in ["Нет даты", "Некорректная дата"]
```

## Установка и запуск проекта

### Требования
- Python 3.10 или выше
- Библиотеки `pandas`, `openpyxl`, `requests`, `pytest`, `pytest-cov`, `flake8`

### Шаг 1: Клонирование и установка зависимостей
```bash
git clone git@github.com:sergeydomrachev30-source/bank_application.git
cd Bank_application
pip install pandas openpyxl requests
```

### Шаг 2: Запуск интерактивного консольного приложения
```bash
python src/main.py
```

### Шаг 3: Запуск тестов и проверка покрытия кода
```bash
pytest
```
Для генерации подробного консольного отчета по покрытию строк тестами выполните:
```bash
pytest --cov=src --cov-report=term-missing
```

### Шаг 4: Проверка кода линтером на соответствие PEP 8
```bash
flake8 src/
```
